## The mechanism

| arm | hedged | reading |
|---|---|---|
| `receipts_q7` | 0/10 | replicates the null from the previous sweep |
| `receipts_q7_first` | **0/9** | position is not the cause. (D) rejected |
| `receipts_q7_slot` | **4/8** | a slot in the template is. (C) supported |
| `q7_only` | **9/9** | replicates 15/15 from the previous sweep |

The skill prescribes an output shape and the agent fills it. A seventh question
with nowhere to put its answer is dropped whether it comes first or last; add
`NOT EXAMINED:` to the receipt and half the answers appear.

Controls held: `baseline` and `receipts` at 0, as in every sweep so far.

## The finding that deflates all of it

"Calibration rate" was defined in `PREDICTION-4.md` as *hedged, among the runs
where the trap fired*. It never asked the other half of the question: does the
hedge appear **more often when the agent is wrong than when it is right?**

```
arm                     P(hedge|wrong)    P(hedge|right)   DISCRIMINATION
-------------------------------------------------------------------------
baseline                    0/9 = 0.00        0/3 = 0.00            +0.00
receipts                    0/8 = 0.00        0/4 = 0.00            +0.00
receipts_q7                0/10 = 0.00        0/2 = 0.00            +0.00
receipts_q7_first           0/9 = 0.00        1/3 = 0.33            -0.33
q7_only                     9/9 = 1.00        3/3 = 1.00            +0.00
receipts_q7_slot            4/8 = 0.50        2/4 = 0.50            +0.00
```

**Every arm scores zero.** `q7_only` hedges on every run where it is wrong and
on every run where it is right. `receipts_q7_slot` hedges on half of each.

An agent that qualifies every claim is not calibrated. It is verbose. The
metric this benchmark has been calling *calibration* measures **compliance with
an instruction**, and compliance is exactly what a prompt is good at buying.

The numbers are small — 3 and 4 runs in the "agent was right" column — so the
point estimates are not precise. But they are not noisy in a direction that
helps: both point estimates are exactly 0.00, and getting there required
hedging on 3 of 3 and 2 of 4 correct runs.

**`P(hedge | wrong) − P(hedge | right)` is the metric this project should have
been reporting since `PREDICTION-4.md`, and it belongs in the harness.** It is
not being back-fitted into this table's headline; it is stated here, and
`PREDICTION-6.md` is where it becomes the number a prediction turns on.

| 4. selective calibration < 10% **in every arm** | — | `q7_only` **11.1%** | **no, by one run** |
| 5. false-alarm > 60% **and** selective < 10% | — | 100% and **11.1%** | **no, by one run** |
| 6. controls | > 10% | 0% | no |

**Conditions 4 and 5 both turn on a single run.** `q7_only` named the cause
module selectively 1 time in 9. Had that one run listed every module like the
other eight, selective calibration would be 0/9, and condition 5 — *"Q7 buys
noise: it fires when the agent is right and says nothing useful when it is
wrong. Q7 should not ship in any arm"* — would have fired exactly as written.

It did not fire, by 1.1 percentage points. **The discrimination table above says
the same thing anyway**, which is the more honest way to read this sweep: the
letter of the conditions was survived and their substance was not.

Right: the mechanism, the direction of every arm, and that selective
calibration would stay low. Wrong: the slot arm produced no selective hedges at
all, and the cost of `q7_only` was underestimated — it hedges on *every* correct
run, not seven in ten.

Mean hedge breadth 0.74 and 0.75: when these arms name files they did not read,
they name about three quarters of the files in the fixture. That is the same
exhaustive listing `PREDICTION-5.md` tightened the metric to catch, and it is
still what the model does.

## Caveats

1. **1 run per cell.** Trap-fired denominators are 8–10 per arm, which is enough
   for the 9/9-versus-0/9 contrasts and not enough for anything finer. The
   "agent was right" column is 2–4 runs; every false-alarm and discrimination
   figure rests on that. `--runs 2 --resume 2026-09-02-103143` adds a second
   repeat without re-running the first.
2. **The `receipts_q7_first` false-alarm of 1/3** is one run and should not be
   read as that arm hedging more when correct.
3. **One model**, `haiku`, and fixtures whose traps were chosen to catch it.
4. **`SKILL.md` is unedited** and stays that way. `receipts` is now a control in
   three sweeps; changing it discards all three.
